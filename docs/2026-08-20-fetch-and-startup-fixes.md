# 2026-08-20 拉取链路与开机启动修复说明

## 问题与根因

1. **重复拉取不叠加**：`daily.py` 只把“本次抓到的文章”写回 `articles.json`，没有与当天旧归档合并。期刊模块又会排除已存档 URL，所以第二次抓取可能把几百篇旧记录覆盖成几篇新增记录。
2. **公众号重新登录后仍无新文**：WeWe RSS 的订阅同步时间停在 8 月 16 日。Docker 关闭期间会错过每天 5:35/17:35 的刷新，重新启用账号本身不会补跑订阅刷新。
3. **某来源失败阻断全部拉取**：公众号抓取在期刊抓取之前且没有异常隔离；WeWe RSS 不可用时，Nature 等外部期刊也不会继续执行。
4. **期刊日/精准状态滞后**：快照只在 Web 自己触发抓取后生成“今天”，终端、定时任务或 AI 写入的归档不会进入快照索引；前端抓取结束后也没有刷新快照区。
5. **部分 ScienceDirect 期刊始终为 0**：RSS 只提供未来卷期月份或缺少精确日期。现增加 ISSN，并以 Crossref 元数据登记日期回退，同时显式排除未来卷期。
6. **本机代理干扰健康检查**：启动脚本的本机 4000/8032 探测会继承 HTTP(S) 代理并收到 502。现改为对 loopback 强制直连。
7. **Docker 与 `.disabled` 文件仍随登录触发**：Docker 的注册表 Run 项被重新创建且 `AutoStart=true`；启动文件夹内的 `daily-push-startup.vbs.disabled` 会被 Windows 当作登录启动文件尝试打开。

## 已实施修复

- 当天文章按稳定 ID/URL 合并，旧数据保留，新数据叠加；重复项以新字段更新。
- 归档写入改为同目录临时文件 + 原子替换；旧 JSON 损坏时停止写入，避免静默清空。
- 公众号、期刊两条链路独立执行；一条失败时另一条继续，日志使用 `[warning]` 明确标记部分失败。
- 当天拉取前逐个触发 WeWe RSS 更新，并通过 `syncTime` 确认真实完成；全部刷新失败时给出重新登录提示。
- 快照 API 自动扫描归档并补齐/更新日期，自定义日期抓取只更新对应日期；前端完成后立即刷新快照。
- 成功但 0 篇的日期也写入空归档，界面可区分“已拉取但无新增”和“从未拉取”。
- ScienceDirect 配置补充 ISSN，日期缺失或仅有未来卷期时按 Crossref 登记日期回退；标题也参与去重，兼容 DOI 与 ScienceDirect 两种链接。
- `start_web.ps1` 对本机健康检查使用 `curl --noproxy '*'`。
- 系统侧已备份 Run 注册表，移走启动文件夹中的 `.disabled` 文件，删除 Docker 登录 Run 值并设置 `AutoStart=false`。备份保留在 `.workbuddy/backup/2026-08-20/`，未删除磁盘文件。

## 验证重点

- 单元测试覆盖旧归档合并、公众号失败时继续期刊、损坏归档保护、代理绕过和快照自动补齐。
- 真实 dry-run 已证明 Nature RSS 可访问；第二次验证发现 4 篇新的 Nature Communications，并得到“旧 268 篇 + 新 4 篇 = 合并后 272 篇”，全程未写现有归档。
- WeWe RSS 主动刷新实测返回“暂无可用读书账号”，数据库账号状态为失效；必须重新扫码登录，而不是只切换启用状态。
- Journal of Membrane Science 的 RSS 100 篇均为未来卷期，Crossref 登记日期回退实测找回 28 篇近期新增。
- Docker 是否不再开机启动仍需下一次 Windows 完整重启后观察；当前注册表与 Docker 配置均已核验为关闭。
