# 抓取互斥与进度可见性修复

## 背景

现场抓取与终端/第三方工具直接执行 `scripts/daily.py` 时，原先只有网页进程内的状态标记，无法阻止两个独立 Python 进程同时抓取同一批公众号与期刊 RSS。并发请求会占用网络与内存，并可能触发来源限流；页面也只能长期显示“抓取中”。

## 本次改动

- `scripts/daily.py` 使用 Windows 文件锁 `data/daily_fetch.lock` 建立跨进程互斥。已有抓取运行时，后续任务立即以退出码 `2` 结束，不会访问任何来源、写入归档或发送邮件。
- `web/paper_observatory.py` 以无缓冲方式流式读取 `daily.py` 输出，并通过抓取状态接口实时返回。
- `scripts/fetch_journals.py` 在请求每个期刊前输出当前期刊名称。
- 页面抓取按钮展示当前阶段或正在请求的期刊；若被互斥锁拦截，明确说明已有任务运行，而非笼统报错。

## 验证

- Python 文件已通过 `py_compile`。
- 前端脚本已通过 Node.js 语法检查。
- 用两个独立 Python 进程验证：第一个持有锁时，第二个进程返回 `lock=busy` 与退出码 `2`；未触发真实抓取。

## 行为说明

文件锁由 Windows 在持锁进程正常退出或异常终止时自动释放。锁文件本身位于受 Git 忽略的 `data/` 目录，不保存抓取内容，也不会阻断后续正常任务。
