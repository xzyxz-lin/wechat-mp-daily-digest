# WeWe RSS 数据目录串用：恢复与防护说明

## 已确认的故障

旧的 Docker 容器使用了另一个项目目录中的 `wewe-rss/data`。该目录中的数据库只保留了空表结构，导致 WeWe RSS 页面显示 0 个订阅、观察台无法获取新的公众号文章。

当前项目的 `wewe-rss/data/wewe-rss.db` 已核对仍包含完整账号、5 个公众号源和 622 篇文章。因此恢复时只切换容器挂载，不覆盖该数据库。

## 本次恢复措施

- 在重建容器前，将完整数据库复制到 `wewe-rss/data/backups/`，作为带时间戳的恢复点。
- 旧容器只会被停止并移除；不会执行卷删除，也不会删除旧目录或任一数据库文件。
- Compose 项目名固定为 `paper-observatory-wewe`，避免多个名为 `wewe-rss` 的目录共享默认项目名。
- 启动脚本始终以当前项目的 Compose 文件和专属项目名执行 `up -d`，不再按泛用容器名复用未知来源的容器。
- 公众号抓取脚本会对 `localhost`、`127.0.0.1` 和 `::1` 直连，避免系统 HTTP(S) 代理把本机 WeWe RSS 请求转发为 502；外部期刊 RSS 仍保留代理支持。

## 恢复后验收

1. 容器挂载源应为本项目的 `wewe-rss/data`。
2. 认证后的 `/feeds/all.json` 应返回已保存文章，而不是空列表。
3. WeWe RSS 网页的“公众号源”应重新显示 5 个订阅。
4. 运行公众号抓取脚本时，不应再出现本机 `localhost:4000` 的 502 错误。

## 仍需关注

期刊 RSS 与公众号 RSS 是两条独立链路。部分出版社会返回 403 或 404，需要单独维护源地址或网络代理；这不影响 WeWe RSS 数据库恢复。
